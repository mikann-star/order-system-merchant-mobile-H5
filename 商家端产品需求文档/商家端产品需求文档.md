# 三、 需求范围

## 产品整体架构

本产品为**餐饮商家端管理系统**，采用**左右分栏**核心布局，左侧为导航区，右侧为内容展示区。

1. 左侧区域

    1. 顶部：展示**餐厅 Logo，**由系统自动生成，Logo 旁展示**餐厅名称，可从店铺设置中修改**

    2. 中下部：功能模块导航栏，点击模块后右侧展示对应页面内容。具体包含以下模块：

        1. 桌台管理

        2. 订单管理

        3. 预订管理

        4. 菜品管理

        5. 服务请求

        6. 客户反馈

        7. 财务统计

        8. 店铺设置

        9. 系统设置

2. 右侧区域

    - 固定展示当前选中模块的完整功能页面

3. 左侧待处理数量展示规则

    1. 适用模块：订单管理、服务请求、客户反馈。

    2. 展示形式：模块对应项右侧显示**红色标签**，标签内为待处理数量。

    3. 规则：有待处理数据时显示红色标签；无待处理时不显示。

# 四、 产品功能详细说明

## 桌台管理

- 该页面为商家端桌台管理核心页面，用于实时监控餐厅桌台状态与点餐操作，默认展示全部区域桌台。

- 页面核心模块包含：

    1. 页面标题与说明

    2. 区域筛选栏

    3. 桌台状态统计栏

    4. 桌台卡片栏

- 页面布局采用**从上至下的纵向流式排布：**

    1. 顶部：页面标题与说明

    2. 标题下方：区域筛选栏

    3. 筛选栏下方：桌台状态统计栏

    4. 统计栏下方：桌台卡片栏（页面主体）

        - **页面标题与说明、区域筛选栏、桌台状态统计栏固定在页面顶部，仅桌台卡片栏支持纵向滚动**，确保商家在滚动查看桌台时，可随时快速筛选、查看全局桌台状态。

### 详情/点餐页面

1. **页面入口**

    1. 快捷入口：状态为「就餐中」的桌台，点击桌台卡片主体区域，可直接进入本页面

    2. 通用入口：所有状态桌台，点击桌台卡片右上角「···」三点菜单栏→「详情 / 点餐」，可进入此页面

2. **全局页面结构**

本页面采用「顶部固定栏 \+ 中部Tab导航栏 \+ 底部内容区」的三段式固定布局，四个子页面共享顶部桌台信息栏与中部导航模块，点击导航栏对应子菜单，即可切换至该子页面内容。

1. **顶部固定栏**

    - **桌台标号：**位于左上角，用大字号加粗展示（如「33号桌」）

    - **桌台状态**：位于桌台标号右侧，展示桌台当前状态\(空闲、就餐中、待清理\)，具体规范如下：

        - 空闲：打勾符号 \+ 英文“available”，整体颜色为绿色；

        - 就餐中：旋转动态符号 \+ 英文“occupied”，整体颜色为蓝色；

        - 待清理：扫帚符号 \+ 英文“cleaning”，整体颜色为橙黄色。

    - **容纳人数**：位于右上角，展示桌台最大容纳人数（如「3人桌」）

2. **中部 Tab 导航栏**

横向排布的功能菜单栏，承载页面内的功能导航：

- 包含四个功能入口：`点餐管理`、`桌台信息`、`折扣信息`、`预订信息`，与子页面一一对应

- 选中态规则：当前激活的 Tab 文字自动加粗，底部增加下划线标识，字体及下划线颜色均为蓝色

- 交互规则：点击任意 Tab，底部内容区实时切换为对应子页面内容。

3. **底部内容区**

对应选中 Tab 的子页面专属内容展示区，支持纵向滚动加载。

#### 点餐管理

页面采用左右分栏布局。左侧面积占比约为60%，为菜品选择区；右侧面积占比约为40%，为订单管理区。

## 预订管理

1. **页面概述：**本板块为商家预订信息的核心管理入口，支持预订信息的查看、筛选、排序、编辑及批量操作。

2. **页面布局**

页面分为三个核心区域，具体如下：

1. **顶部统计区**：实时展示当日预订核心概览数据，包含总预订数、待就餐数、已就餐数、已取消数；

2. **中部操作区**：包含「新增预订」功能按钮、「批量删除」功能按钮；

### 顶部统计区

顶部统计区采用横向均匀排布方式，展示4个数据统计卡片，分别对应总预订数、待就餐数、已就餐数、已取消数，所有数据均实时同步当日预订数据。

### 中部操作区

中部操作区采用靠右排列布局，从左至右依次排布「新增预订」按钮、「批量删除」按钮。

        2. **「全选」复选框**

            - 状态 1：全选

                - 此时再次点击「全选」框，会取消所有列表项的勾选，实现 “一键清空所有筛选条件”。

                - 当用户手动勾选了部分列表项、未勾选全部时，「全选」框显示为黑色方块（半选状态）。

                - 当用户取消所有列表项的勾选时，「全选」框变为空白。此时点击「全选」框，会一键勾选所有列表项，恢复显示全部数据。

#### 订单金额统计

订单各金额字段定义及计算公式如下：

- **原价**：所有原价之和

- **菜品优惠**：所有原价\-所有菜品折后价

- **退款金额**：所有已退款菜品折后价之和

- **整单优惠**：根据所设置的整单优惠类型，其计算方式如下：

    - 百分比折扣：（原价\-菜品优惠\-已退款金额）×折扣百分比

    - 固定金额减免：固定减免金额——根据父订单金额比例进行减免即可

- **待/实付金额**：用户实际支付的金额，计算方式为：原价 \- 菜品优惠 \- 已退款金额 \- 整单优惠；若订单支付状态为待支付，则展示待付金额；若订单支付状态为已支付，则展示实付金额。



**特殊说明**：

- 若当前订单无菜品折扣/整单折扣/退款金额，则不做该项的展示

- 结合当前业务场景（多数订单为就餐完毕后进行结账），退款操作均发生于结账前，故退款金额以菜品当前折后售价为准，不包含整单折扣减免部分。

3. **同步字段展示**

    可见文档：[「同比」功能](https://zcn60d6o2fbp.feishu.cn/docx/PeXsdwFK0oJEjlxYoSqc9Ed4nYe?from=from_copylink)

    1. **通用规则（所有时间维度均适用）**

        1. 数据对比核心逻辑

            1. 对比公式：**增长率=\(本期值\-上期值\)/上期值×100%**

            2. 特殊值处理：上期值为0时，不展示增长率

            3. **核心样式规范**：

                1. 增长率计算后**四舍五入保留小数点后两位；**展示**「箭头 \+ 增长率绝对值 \+%\+同比」**；【同比】为黑体，其余部分根据增长率正/负与否，显示绿色/红色

                2. 正增长：**绿色**向上箭头（↑）\+ 增长率绝对值，例：↑13\.65%（绿色）

                3. 负增长：**红色**向下箭头（↓）\+ 绝对值，例：↓8\.23%（红色）

                4. 零增长：**黑色横杠（—）\+ 0\.00%**，例：—0\.00%（黑色）；

            4. 异常兜底：上期无数据/数据不足时，灰色提示「上期数据不足，无法对比」，不展示指标

        2. 前端通用展示

            1. 展示位置：所有时间维度的「同比」指标，统一展示在对应数值下方

            2. 触发方式：选择对应时间维度并查询后，自动展示，无需用户额外操作

    2. **细分维度「同比」规则（今日/昨日/近7日/近30日）**

        1. 今日

            1. 本期时间范围：**自然日今日**（00:00\-当前时间，实时更新）

            2. 上期时间范围：**自然日昨日**（与本期同时间段，如今日00:00\-14:00 → 昨日00:00\-14:00）

        2. 昨日

            1. 本期时间范围：**自然日昨日**（00:00\-23:59，完整单日）

            2. 上期时间范围：**自然日前日**（00:00\-23:59，完整单日，即昨日的前一天）

            3. 特殊处理：无实时性要求，固定取完整昨日数据与前日对比，无需时段匹配

        3. 近7日

            1. 本期时间范围：**近7个自然日**（含当日，如2026\.1\.25\-2026\.1\.31），固定按自然日计算，非滚动7天

            2. 上期时间范围：**前7个自然日**（本期向前偏移7天，如2026\.2\.18\-2026\.1\.24），保证同期同跨度

        4. 近30日

            1. 本期时间范围：**近30个自然日**（含当日，固定自然日计算，非滚动30天）

            2. 上期时间范围：**前30个自然日**（本期向前偏移30天），同期同跨度对比

    3. 自定义时间范围「同比」规则

        1. 本期时间范围：用户手动选择的**开始日期\-结束日期**（含首尾，自定义天数N）

        2. 上期时间范围：以本期结束日期为基准，**向前偏移N天为上期结束日期，再向前偏移N天为上期开始日期**（严格同期同跨度）

        3. 示例：自定义2026\.1\.1\-2026\.3\.3（N=62天）→ 上期2025\.10\.31\-2025\.12\.31（62天）

        4. 特殊处理：自定义N=1天时，即开始日期=结束日期

            - 若所选日期为今日，则采用【今日】的较上期规则

            - 若所选日期不为今日，直接复用「昨日」的较上期规则

### 数据指标

|字段|字段定义|计算公式|
|---|---|---|
|销售总额|所有订单的原始标价总和，未扣除任何折扣、退款。|销售总额 = Σ（每笔订单原始标价）|
|退款金额|所有已完成退款的金额总和。|退款金额 = Σ（每笔已完成退款的金额）|
|营业总额|有效成交的订单总额，仅扣除退款，未扣除折扣。|营业总额 = 销售总额 \- 退款金额|
|实收金额|商家实际到账的金额，即扣除所有退款、折扣后的最终收款。|实收金额 = 营业总额 \- 折扣总额<br>|
|退款率|订单退款金额占销售总额的比例。|退款率 = （退款金额 ÷ 销售总额）× 100%|
|订单总数|所有已下订单数量，含已取消与未取消。|订单总数 = 所有已下订单数量|
|有效订单数<br>|实际成交的订单数量，即未取消的订单数。1\.0版本中可判定为未整单退款的订单数。|有效订单数 = 订单总数 \- 整单退款订单数|
|客单价|每笔有效父订单的平均成交金额。|客单价 = 实收金额 ÷ 有效父订单数|
|人均消费|每位顾客的平均消费金额。|人均消费 = 实收金额 ÷ 顾客总量（注：顾客总量为父订单下的顾客数量之和）|
|商品总成本|未退款的菜品成本总额与已退款但未加回库存的菜品成本总额之和。|商品总成本 = 未退款菜品成本总额 \+ 已退款且未加回库存菜品成本总额|
|毛利总额|实收金额扣除商品本身成本后的利润。|毛利总额 = 实收金额 \- 商品总成本|
|综合毛利率|毛利总额占实收金额的比例，反映整体盈利效率。|综合毛利率 = （毛利总额 ÷ 实收金额）× 100%|
